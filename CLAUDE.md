# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Phishing Shield is a small Manifest V3 browser extension: its popup inspects the active tab's URL
and highlights phishing/spoofing signs (brand look-alikes, brand names on other sites, a login before
`@`, non-HTTPS, raw IP hosts, unusual ports, punycode homographs, odd characters). An opt-in toolbar
badge shows the verdict for every page. Plain HTML/CSS/JS, no build, no runtime dependencies (ESLint
is dev-only).

## Running

`chrome://extensions` → Developer mode → **Load unpacked** → this folder, then pin it and click
the icon on any page. After edits, press **Reload** on the extension card. `npm test` runs
`popup.js` and `background.js` against fake tabs, a fake `chrome` API and a minimal fake DOM
(verdicts, PSL splitting, brands, text-only rendering, the toggle, badges). Still check by hand: a
normal HTTPS site, an `http://` site, a punycode domain, a `co.uk`-style domain, a `chrome://` page,
and the toolbar toggle (permission prompt, badges appear, unticking clears them).

## Code

- `manifest.json`: MV3, popup action, permission `activeTab`, **optional** permission `tabs`,
  service worker `background.js`.
- `lib/analyze.js`: all checks, pure (no DOM, no network). `analyzeUrl(url)` returns
  `{ level, findings, parts }`: findings sorted by `SEVERITY_ORDER` (first = headline), parts = the
  URL split for display with a role (`dim`, `danger`, `warn`, `main`, `main-danger`, `main-warn`).
  Registrable domain via the PSL (`publicSuffix`); trailing-dot FQDNs keep `mainDomain` (shown)
  apart from `checkDomain` (checked). Brand checks (`brandFindings`) use look-alike character
  normalisation, edit distance (8+ letters only) and `PHISH_WORDS` padding.
- `lib/brands.js`: brands with `keywords`, `domains` (real ones; first is shown) and
  `commonWords` (ordinary-word keywords that need a phishing word nearby). Add a test with each new
  brand showing its real domains still pass.
- `lib/psl-data.js`: generated by `scripts/update-psl.mjs` (`npm run update-psl`), MPL-2.0, excluded
  from lint. Never edit by hand.
- `popup.js`: renders the result and the toolbar-verdict toggle (`chrome.permissions` request/remove).
- `background.js`: `importScripts` the three lib files; while `tabs` is granted, sets each tab's
  badge on `tabs.onUpdated`, and refreshes or clears all tabs on `permissions.onAdded/onRemoved`.
- `popup.html` loads `lib/psl-data.js`, `lib/brands.js`, `lib/analyze.js`, `popup.js` in that order;
  the test harness's `SCRIPTS` list must match. `popup.css`: colour tokens on `:root`, dark values
  under `prefers-color-scheme: dark`. `icons/icon.svg` is the source of the PNG icons.

## Rules

- **Never put URL-derived text in as HTML.** Build nodes with `createElement` and set
  `textContent`; no `innerHTML`. The URL is attacker-controlled. Colours are CSS classes/tokens.
- Keep permissions minimal: `activeTab` at install; `tabs` stays optional and opt-in. No network
  requests, no remote code; the PSL and brand list are bundled.
- These are heuristics, not verdicts; keep the README's limitations honest. When tuning the brand
  checks, run them against everyday domains too: false alarms cost more trust than a missed typo.
- README screenshots in `docs/screenshots/` are rendered from the real popup files with a stubbed
  `chrome` (tabs.query, permissions.contains) in headless Edge at 2×; force light mode with
  `--blink-settings=preferredColorScheme=1` (dark: `=0`), since headless follows the system theme.
  Regenerate them if the popup's look changes.

## App standards

This repo follows the app standards in `~/Desktop/code/tools/standards/STANDARDS.md` (rule IDs,
severities; decisions and waivers in `.claude-standards`). `claude-check --repo .` checks it.

```sh
npm ci && npm run lint   # ESLint (dev-only), incl. the no-unsanitized rule; CI runs it too
npm test                 # the tests CI runs
```

Unsafe DOM sinks (no-unsanitized) are lint **errors** and fail CI. Unused variables are still
warnings. Other errors (eval, undefined names, parse errors) fail CI too.
